# 개인 가계부 CLI 애플리케이션 (`budget_app`)

터미널 환경에서 가계 경제 활동을 기록, 조회, 통계 분석, 관리할 수 있는 순수 파이썬(Python 3.10+) 기반의 CLI 가계부 애플리케이션임.  
수입/지출 내역 기록, 다중 조건 검색, 월별 요약 통계 및 예산 관리, 카테고리 관리, CSV 가져오기/내보내기 기능을 제공하며, 100% 파이썬 표준 라이브러리만을 사용하여 외부 패키지 설치(`pip install`) 없이 즉시 실행 가능함.

## 1. 아키텍처 및 모듈 구조

소프트웨어 공학의 **단일 책임 원칙(SRP)**과 **관심사의 분리(SoC)**를 기반으로 4개 계층(Layer)으로 분리 설계됨.

```text
budget_app/
├── __init__.py      # [패키지 선언] 폴더를 파이썬 패키지로 인식시키는 초기화 파일
├── __main__.py      # [진입점 부트스트랩] python -m budget_app 실행 시 sys.path 보정 및 CLI 기동
├── models.py        # [데이터 모델 계층] Transaction 데이터 규격 및 직렬화/역직렬화 정의
├── storage.py       # [저장소/I-O 계층] 3개 분리 JSONL 파일 입출력, 제너레이터 스트리밍, 원자적 교체
├── service.py       # [비즈니스 로직 계층] 데이터 집계, 통계 연산, 유효성 검증, 파사드 인터페이스
└── cli.py           # [사용자 인터페이스 계층] 인자 파싱, 대화형 프롬프트, 터미널 화면 렌더링, 종료 코드 제어
```

### 계층별 핵심 역할 및 설계 근거
1. **CLI 계층 (`cli.py`)**: 사용자 입력 접수, 옵션 파싱, 전역 예외 포획(`@cli_handler`), 콘솔 테이블 렌더링을 전담함.
2. **서비스 계층 (`service.py`)**: 비즈니스 룰 검증, 통계 연산, 다중 필터링을 전담하며, CLI가 Storage를 직접 호출하지 못하도록 파사드(Facade) 인터페이스를 제공함.
3. **저장소 계층 (`storage.py`)**: 3개 분리 파일 영구 저장, 제너레이터(`yield`) 기반 대용량 스트리밍 읽기, 원자적 파일 교체(`os.replace`)를 전담함.
4. **모델 계층 (`models.py`)**: 도메인 데이터의 필드 규격(`Transaction`) 및 JSON 상호 변환(`to_dict`, `from_dict`)을 전담함.

## 3. 저장 파일 위치 및 원자적 교체 메커니즘

데이터는 **3개의 분리된 JSONL(JSON Lines) 파일**에 영구 저장됨.

| 파일명 | 저장 포맷 | 설명 및 저장 데이터 규격 |
| :--- | :---: | :--- |
| `data/transactions.jsonl` | JSONL | 전체 수입/지출 거래 내역 (행당 1건, 고유 8자리 ID 보유) |
| `data/categories.jsonl` | JSONL | 사용 가능한 카테고리 목록 (기본값: 식비, 교통, 쇼핑, 급여, 기타) |
| `data/budgets.jsonl` | JSONL | 연월(`YYYY-MM`)별 설정된 지출 목표 예산 금액 |

### 원자적 파일 교체 (Atomic File Replacement)
데이터 수정, 삭제, 카테고리 삭제, 예산 설정 시 일반 파일 쓰기(`open(..., "w")`)를 사용하지 않음. 일반 쓰기는 파일을 여는 즉시 기존 내용이 0바이트로 잘려나가 쓰기 도중 프로세스가 비정상 종료되면 데이터가 영구 소실됨.  
본 애플리케이션은 **`tempfile.NamedTemporaryFile`로 임시 파일에 데이터를 완벽하게 작성한 후, 운영체제 시스템 콜인 `os.replace`로 디렉토리 엔트리를 나노초 단위로 원자적 교체**함. 이를 통해 정전, 강제 종료(`Ctrl+C`), OS 크래시 상황에서도 원본 데이터가 절대 손상되지 않음.

## 5. import / export CSV 스키마

CSV 파일은 **UTF-8 인코딩**과 **헤더 라인**을 포함해야 함.

| 컬럼명 (Header) | 필수 여부 | 데이터 타입 | 유효성 검증 규칙 및 형식 예시 |
| :--- | :---: | :---: | :--- |
| `date` | 필수 | String | 실존하는 날짜 (`YYYY-MM-DD`, 예: `2026-09-12`) |
| `type` | 필수 | String | 거래 구분 (`income` 또는 `expense`만 허용) |
| `category` | 필수 | String | 카테고리명 (미등록 카테고리 시 자동 생성됨) |
| `amount` | 필수 | Integer | 0보다 큰 양의 정수 (원 단위) |
| `memo` | 선택 | String | 거래 상세 메모 (누락 시 빈 문자열 처리) |
| `tags` | 선택 | String | 쉼표(`,`)로 구분된 태그 목록 (예: `외식,주말`) |

## 6. CLI 옵션 표기 규칙 및 오류 처리/종료 코드 규격

### (1) CLI 옵션 표기 규칙
* **단일 대시(`-`) 통일 지원**: `-limit`, `-from`, `-to`, `-category`, `-type`, `-q`, `-tag`, `-month`, `-top`, `-amount`, `-id`, `-fallback`, `-out`, `-data-dir` 등 단일 대시(`-`) 표기를 기본 지원하며, 이중 대시(`--`)도 동시 지원함.

### (2) 오류 처리 규격 (스택트레이스 차단)
사용자의 잘못된 입력 또는 검증 실패 시 파이썬 트레이스백을 노출하지 않고, 원인과 해결 힌트를 친절하게 2줄로 제공함.

```text
❌ 오류 [원인]: -month에 존재하지 않는 월이 입력되었습니다. (입력값: '2026-13')
💡 해결 힌트: 01~12월 범위의 유효한 연월을 입력하세요. (예: 2026-09)
```

### (3) 종료 코드 (Exit Code) 완전 대조표
운영체제 프로세스 레벨에서 명령어 성공 및 실패를 명확히 구분함.

| 상황 | 설명 | 종료 코드 | 터미널 확인 (`echo $?`) |
| :--- | :--- | :---: | :---: |
| **정상 완료** | 모든 명령어가 정상 실행되고 완료된 경우 | `0` | `0` |
| **명령어 누락** | `python -m budget_app` 단독 실행 시 도움말 출력 후 오류 종료 | `1` | `1` |
| **서브커맨드 누락** | `python -m budget_app budget` 하위 명령어 누락 시 오류 종료 | `1` | `1` |
| **인자 파싱 오류** | `-top ABC` 등 잘못된 타입 입력 시 오류 종료 | `1` | `1` |
| **유효성 검증 실패** | 가짜 날짜(`2026-02-31`), 음수 금액, 미등록 카테고리 등 | `1` | `1` |
| **사용자 작업 취소** | 대화형 입력 중 사용자가 `Ctrl+C`를 누른 경우 | `130` | `130` |
